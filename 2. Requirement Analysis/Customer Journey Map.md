# Public website visitor journey

| Step | Visitor action | Intended response |
| --- | --- | --- |
| Orient | Open Home | Brief HDI explanation, three dimensions, verified data highlights and clear next actions |
| Explore | Select countries, region and year | Published indicators, historical comparison, exact values and explicit missing records |
| Estimate | Use a preset and adjust four inputs | Validation, genuine model estimate, category and separate formula reference |
| Compare | Open Scenarios and change indicators | Hypothetical score difference, dimensions and reset |
| Configure AI | Open the navbar key icon; enter a personal Groq key | Masked input, privacy explanation and memory-only configured status; no automatic request |
| Understand | Explicitly generate an explanation | Server-recomputed evidence sent to Groq; clear success, credential, limit or availability feedback |
| Manage key | Change/remove it or refresh | Local key/answer cleared as appropriate; refreshing requires key entry again |
| Review | Open Methodology | Measured evaluation, model selection, formula and limitations |
| Share | Export a data table or result | Labeled JSON with source/model context and no credential |

Core exploration, prediction and scenarios need no account or API key. Mobile visitors use the top navigation dropdown and retain access to AI Settings. The website explains that its hosting server receives the key for requested AI operations; visitors should only enter keys on sites they trust. The current Chrome workflow, mobile and personal-key checks are recorded in folder 6. Broader human device testing remains useful.
